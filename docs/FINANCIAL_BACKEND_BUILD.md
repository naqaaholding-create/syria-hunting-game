# بداية بناء الربط المالي — رحلة صيد

## ما أُنشئ في هذه المرحلة

- Node.js 20+ / Express API skeleton.
- HTTP security headers عبر Helmet.
- اتصال PostgreSQL اختياري عبر `DATABASE_URL`.
- `GET /health` لفحص حالة الخدمة والإعدادات دون كشف الأسرار.
- مسارات مالية مغلقة افتراضيًا؛ لا يمكنها إصدار رصيد أو إرسال أموال.
- إعدادات TRON Shasta الاختبارية في `.env.example`.
- ملف SQL الأساسي موجود في `backend/schema/financial_schema.sql`.

## تشغيل محلي

1. ثبّت Node.js 20 أو أحدث وPostgreSQL.
2. من مجلد `backend` نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env` واملأ `DATABASE_URL` محليًا فقط.
4. نفّذ `npm run check` ثم `npm start`.
5. افتح `http://localhost:8080/health`.
6. لا تفعّل الإيداعات أو السحوبات في هذه المرحلة.

## خطة التنفيذ التالية

1. ترحيلات SQL قابلة للتكرار، وقيود دفتر الأستاذ المتوازن، ومنع تعديل القيود المرحلة.
2. تسجيل دخول آمن وجلسات/رموز قصيرة العمر، وصلاحيات لاعب/مدير، ومصادقة متعددة العوامل للإدارة.
3. إنشاء حسابات المحفظة عند التسجيل، وعمليات دفتر أستاذ ذرية مع مفاتيح idempotency وقفل الأرصدة.
4. استقبال USDT TRC-20: تخصيص/ربط عنوان إيداع لكل مستخدم، مراقبة أحداث الشبكة من مصدر موثوق، تأكيدات كافية، تحقق من عقد USDT الرسمي للشبكة المختارة، كشف إعادة التنظيم/التكرار، ثم قيد مالي بعد التحقق فقط.
5. السحب: طلب موثّق، حجز الأرباح داخل معاملة قاعدة بيانات، حدود ومكافحة احتيال، موافقة إدارية منفصلة، ثم تنفيذ عبر موقّع/مزود آمن مستقل عن خادم الويب، مع مفتاح idempotency وتسجيل txid والتحقق من النتيجة.
6. اختبارات وحدات وتكامل، اختبارات فشل وإعادة إرسال، مراجعة أمنية وقانونية ومحاسبية.
7. بعد نجاح Shasta، تخطيط انتقال مضبوط إلى Mainnet مع حدود تشغيلية ومراقبة وتنبيهات.

## ضوابط مهمة

- SafePal هي محفظة المستخدم الخارجية؛ لا نطلب ولا نخزن عبارة الاسترداد أو المفتاح الخاص للمستخدم.
- لا تضع مفاتيح TronGrid أو أي أسرار في GitHub؛ `.env` مستثنى من Git.
- لا تعتمد على لقطة شاشة أو رسالة من المتصفح كإثبات إيداع؛ تحقق من السلسلة والعقد والمبلغ والعنوان والتأكيدات.
- لا تستخدم رصيد USD داخل اللعبة على أنه أموال فعلية تلقائيًا. دفتر اللعبة بالدولار المحاسبي، والتحويل الحقيقي يتطلب تسوية موثقة.
- جميع وظائف الإيداع والسحب معطلة عمدًا في الهيكل الحالي. وجود المسار لا يعني أن التحويل جاهز.
